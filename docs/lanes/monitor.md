# Lane monitor

**You build:** `src/monitor/` — the price truth monitor: promo gap snapshot, daily cart sample, collector ingest, read model.
**Keep these exports:** in `src/monitor/index.ts` `runPromoGapSnapshot: Job`, `runCartSample: Job`, `createPriceTruthReadModel(db): PriceTruthReadModel`; in `src/monitor/routes.ts` `ingest: Hono<AppEnv>` (mounted at `/ingest` behind the ingest token).
**Read first:** `src/contracts/reports.ts` (PromoGapSnapshot, WorstGapDeal, CartSampleDay, PublicPriceComparison, PriceTruthReport), `src/contracts/ingest.ts`, `src/contracts/ports.ts` (Job, Deps, CartService, CatalogueStore), `migrations/0003_prices.sql`, `src/lib/money.ts` (`gapShare`).
**Test with:** `createTestDb()` + `seedCatalogue(db)` for the SQL parts, `makeWorld()` for the cart sample, `createApp({ deps })` for the ingest route.

## Behaviour

1. **Promo gap snapshot** (`promo-gap`): over listable products and their sellable options (`active` not 0). `optionsWithPromo` counts options with `promo_amount` lower than `retail`. `medianGap` and `p90Gap` over `(retail - promo) / retail` of those options (nearest-rank percentile; say so in a comment). Compute in SQL with `ORDER BY ... LIMIT 1 OFFSET k`; never load all options. No promo options: gaps are 0. One row per run in `promo_gap_snapshots` (`taken_at` = now).
2. **Cart sample** (`cart-sample`): `env.CART_SAMPLE_SIZE` options (default 20, cap 50) from `catalogue.sampleListableOptions(n, <UTC day>)`. For each: `carts.create([{ ..., quantity: 1, expectedPriceMinor: retail }], "monitor")`, one `cart_samples` row (`matched` when the cart line's retail equals the expected price; `price_mismatch` with `current_minor`; `unavailable`; `error` with the code), then **abandon the cart at once**. A run that already has rows for today does nothing (one sample per day). Summary: counts per outcome.
3. **Ingest** `POST /ingest/observations` with an `IngestBatch`: validate every field (types, `https://www.groupon.com/` prefix on URLs, integers for money, ISO time, at most `INGEST_MAX_OBSERVATIONS`, body at most 512 KB). Invalid items are rejected one by one with a reason; valid ones are stored. `public_prices`: match `permalink` to `products.reference` (exact, then case-insensitive) and set `matched_product_id` and the matched option = the default option, else the cheapest sellable one. Duplicate `(permalink, observed_at)` is ignored. `guide_version`: one `guide_observations` row. Answer `IngestReceipt`.
4. **Read model** `report(days)`: latest snapshot, history (one per day, newest per day), worst 50 gaps, cart samples per day, public comparison per day (`showsRetail` when the public price equals the matched option's current `retail`, `showsPromo` when it equals its promo amount, else `showsOther`), price changes per day from `price_changes`. Days without data are left out, not filled with zeros.

## Tests you must have

Snapshot numbers on the fixtures by hand calculation (state them in the test); snapshot with no promos; sample writes one row per option and abandons every cart (`world.carts.log` has no open cart); sample after `partner.setRetail` records a mismatch; second run the same day does nothing; ingest accepts, rejects, deduplicates, matches; oversize batch refused; report shape with and without data.
