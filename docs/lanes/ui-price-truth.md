## Behaviour

1. **Document**: `shell({ title: "Price truth", active: "price-truth", body })`. Body in order: the hero (eyebrow "Product 1 · Price truth monitor", h1 "Price truth", the lead is the verdict sentence), the verdict banner, the tiles, the four sections in the board's order, the foot line.
2. **`verdictOf(report)`** returns `{ tone, title, text }`. The newest cart day is the `cartSamples` entry with the largest `day`; the newest public day the `publicComparison` entry with the largest `day`. Pass (tone `pass`) when the newest cart day has `priceMismatch === 0` and `errors === 0`, and the newest public day has `showsOther === 0`: title as the board words it, text "The price the API quotes is the price the cart charges: <matched> of <sampled> carts on <day>. groupon.com showed the same price on <showsRetail> of <matchedDeals> listing pages on <day>." Fail (tone `fail`) when either disagrees: the same sentence with the counts that disagree named first. Neutral when there is no day yet: "The first cart sample runs at 04:30 UTC; the public comparison follows the collector's first run." The lead of the hero is the verdict text.
3. **The tiles** (`statTiles(…, { panel: true, lead: true })`): from `report.latest` (promo share, median gap, p90 gap, the total gap in money) as the board draws them; before the first snapshot, the existing "No snapshot yet" sentence in `emptyState` instead.
4. **Sections**, each a `section` with the title and lead from the board and a sentence that names when it refreshes:
   - Catalogue against cart: `dayStrip` over the last 30 days of `cartSamples` (tone pass when `priceMismatch === 0 && errors === 0`, fail otherwise, the title `<day>: <matched> of <sampled> matched`), then the newest day's numbers as the board shows them, then the table of days (`dataTable`, the existing columns).
   - API against groupon.com: the same strip over `publicComparison` (pass when `showsOther === 0`), the newest day's numbers, the table.
   - Promo gap, whole catalogue: the histogram of `gapBands` as today, then the largest gaps as `rankList` rows (rank, the deal linked, cells: You pay = `retailMinor`, With code = `promoMinor`, Gap = percent, Code = the code or "no code"), at most as many as the report holds; this page is the monitor of the gap, so the promo price is shown here as "With code", never as "You pay".
   - Freshness: `priceChangesPerDay` as histogram bars, and the sentence with `nextDeltaText(now)`.
5. **Foot line**: `pageFoot` with the schedule sentence (the promo gap snapshot daily at 04:30 UTC, the cart sample daily at 04:30 UTC, the delta sync every 3 hours, the next one at `nextDeltaText(now)`).
6. The acceptance script reads these words, so keep them on the page: "carry a promo code" and "median" in the promo gap section, a heading "Largest gaps" over the ranked gaps, the section titles "API against groupon.com", "Catalogue against cart" and "Freshness" in that text, the day (`YYYY-MM-DD`) of every row of the cart and public tables, and in Freshness a time `hh:mm UTC`. The app test reads the public comparison table's four numbers in adjacent `<td>` cells. Every empty case keeps a sentence with a time. Every value through `esc`, money only through `formatMoney`. Never "no data". No `Date.now()`.
